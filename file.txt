# Save uploaded resume to db
Implement the service logic for an existing upload-resume REST API. This task involves integrating AWS S3 for file storage and PostgreSQL for metadata persistence.

1. Database Schema (PostgreSQL)
Create a table named resume_metadata with the following specification:
id: UUID or String (Primary Key).
user_id: String (Foreing Key Indexed).
s3_key: String (Unique; stores the path/URL returned from S3).
status: Enum with values PENDING, SUCCESS, FAILED.
uploaded_at: Timestamp (Defaults to current time).
size: Float (File size in bytes or KB).

2. Functional Requirements & Logic Flow
Implement a service function that handles the following sequence:
Identity Resolution: Check if a user_id is provided. If the user is unregistered (no ID provided), generate a dummy user_id (e.g., guest_[unique_suffix]) to associate with the resume.
Initial Persistence: Create a record in resume_metadata with the status set to PENDING.

3. S3 Integration: * Accept .pdf and .docx file types.
Upload the file to an S3 bucket.
Capture the returned s3_key or Object URL.

4. Finalize Record:
On Success: Update the database record with the s3_key, the calculated file size, and change the status to SUCCESS.
On Failure: If the S3 upload fails, update the database status to FAILED and log the error.

3. Technical Constraints
Ensure the file size is calculated correctly before or during the upload.
Use a clean, modular approach (e.g., separating the S3 client logic from the database repository logic).
Provide the SQL DDL for the table and the Enum type.

Output Expectations:
SQL migration script for the PostgreSQL table.

# Parse resume

## Goal
The current upload-resume API should extracts raw text, uses an LLM to convert resume text into structured JSON, validates the output, and stores parsed data for downstream features.

The parsed output must support:
1. ATS Score
2. Resume strengths
3. Weak sections
4. Missing keywords
5. Formatting suggestions
6. Job Match Score
